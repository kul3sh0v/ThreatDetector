# ThreatDetector (cron + sudo + ssh)

Лёгкий детектор для Linux, который ищет:
- потенциальные инъекции в заданиях `cron`;
- подозрительные вызовы `sudo` по логам;
- аномалии в SSH-логах (брутфорс, подозрительные IP, нетипичные пользователи и подключения).

Сканеры запускаются по ключам или все сразу по умолчанию.

## Возможности

### Cron‑сканер
- Проверяет:
  - `/etc/crontab`
  - `/etc/cron.d/*`
  - пользовательские crontab’ы: `/var/spool/cron`, `/var/spool/cron/crontabs`
  - скрипты: `/etc/cron.hourly`, `/etc/cron.daily`, `/etc/cron.weekly`, `/etc/cron.monthly`
- Ищет типичные индикаторы компрометации в командах.
- Сортирует находки по уровню критичности (`ВЫСОКИЙ/СРЕДНИЙ/НИЗКИЙ/ИНФО`).

### Sudo‑сканер
- Анализирует `/var/log/auth.log` или `/var/log/secure`.
- Проверяет `sudo.log`, если он настроен через `Defaults logfile=...` или есть `/var/log/sudo.log`.
- Ищет:
  - подозрительные команды (`curl|wget|bash|chmod +s|useradd|visudo|chown root`),
  - частые sudo‑вызовы за короткий период,
  - sudo без TTY,
  - запуск от нетипичных пользователей (сервисные аккаунты),
  - запуск из нетипичных мест (`/tmp`, `/dev/shm`, `/run`).

### SSH‑сканер
- Анализирует SSH-события в:
  - `/var/log/auth.log*`
  - `/var/log/secure*`
  - `/var/log/messages*`
- Сканирует как активные, так и ротационные логи, включая архивы `.gz`, `.xz`, `.bz2` (формат `.zst` не поддерживается).
- Ищет:
  - брутфорс SSH по IP,
  - подозрительные IP с перебором пользователей (password spray / invalid user burst),
  - попытки входа в `root`,
  - нетипичных пользователей (включая сервисные аккаунты),
  - успешный вход после серии неудачных попыток,
  - подозрительные подключения и протокольные аномалии (`POSSIBLE BREAK-IN ATTEMPT`, `Bad protocol version`, `Unable to negotiate` и т.п.).

## Требования

- Linux.
- Python 3.8+.

## Установка

Зависимостей нет. Достаточно Python.

## Использование

Запустить все сканеры (по умолчанию):
```bash
python3 tdetect.py
```

Только cron:
```bash
python3 tdetect.py -c
```

Только sudo:
```bash
python3 tdetect.py -s
```

Только SSH:
```bash
python3 tdetect.py -h
```

Только sudo + SSH:
```bash
python3 tdetect.py -sh
```

Дополнительные пути/логи и вывод в файл:
```bash
python3 tdetect.py --cron-paths /etc/cron.d /var/spool/cron --sudo-logs /var/log/auth.log --ssh-logs /var/log/auth.log.1 /var/log/secure --output /tmp/report.txt
```

Справка по аргументам:
```bash
python3 tdetect.py --help
```

## Формат отчёта

Отчёт разбит по секциям:
```
=== CRON ===
...

=== SUDO ===
...

=== SSH ===
...
```

Каждая находка включает:
- уровень критичности,
- источник и строку,
- причину,
- деталь/команду (если есть),
- пользователя/IP (если есть).

Пример вывода:
```
=== SSH ===
[ВЫСОКИЙ] /var/log/auth.log:213 брутфорс SSH (ip=203.0.113.25)
  деталь: 11 неудачных попыток за 300 сек (2026-02-23 10:14:02 - 2026-02-23 10:18:53), users=root,admin,test

[ВЫСОКИЙ] /var/log/auth.log:220 успешный вход после серии неудачных попыток (user=root, ip=203.0.113.25)
  деталь: 9 неудачных попыток за 900 сек перед успехом
```

## Настройка sudo.log

Чтобы включить отдельный лог sudo, добавьте в `/etc/sudoers` или файл в `/etc/sudoers.d` строку:
```
Defaults logfile="/var/log/sudo.log"
```
После этого сканер автоматически проверит этот файл.

## Ограничения и ложные срабатывания

- Логи могут быть неполными/ротационными — часть событий может отсутствовать.
- Сервисные аккаунты могут легитимно выполнять `sudo` или входить по SSH в автоматизации — это даст предупреждение.
- Некоторые легитимные команды/подключения могут совпасть с «подозрительными» паттернами.
- На системах без нужных логов сканеры не найдут событий (будет выведено `INFO`).

## Важно

Это эвристический детектор. Он помогает быстро сузить поиск, но:
- не гарантирует наличие вредоносных действий;
- не заменяет анализ журналов, контроль целостности и сетевой мониторинг.
